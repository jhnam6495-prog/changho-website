## A. 레이아웃 / 스타일 이슈

### A1. 섹션 탭 메뉴가 스크롤해도 상단에 고정되지 않음

- **증상**: 페이지를 스크롤하면 `position: sticky`로 만든 탭바가 고정되지 않고 콘텐츠와 함께 그대로 흘러가 버림
- **원인**: `globals.css`의 `html { overflow-x: hidden }`이 `body`의 overflow가 뷰포트로 전파되는 것을 막아, `body`가 "실제로는 스크롤되지 않는 별도의 스크롤 컨테이너"로 취급됨. 그 결과 `sticky` 요소의 기준이 화면(viewport)이 아니라 이 `body`가 되어버려 고정되지 않음
- **해결**: `overflow-x: hidden`을 `html`에서 제거하고 `body`에만 남김. 가로 스크롤 방지 효과는 동일하게 유지되면서 sticky가 정상 동작

헤드리스 브라우저로 실제 스크롤 후 `getBoundingClientRect()`를 측정해 재현 → 수정 후 스크롤 위치와 무관하게 `top` 값이 고정되는 것을 확인.

### A2. 인증서 PDF 미리보기 박스에서 세로 스크롤 발생

- **증상**: 좁은 화면에서 카드 안 PDF 미리보기가 넘쳐 스크롤바가 생기고, 활성 탭 밑줄과 겹쳐 보임
- **원인**: CSS `aspect-ratio` + `max-width: 100%` 조합은 폭이 줄어드는 상황에서 높이가 함께 줄지 않아, 실측 결과 비율이 `0.573`로 나와야 할 `0.707`(A4 비율)과 어긋남 — 즉 박스가 필요 이상으로 길어져 내부 콘텐츠가 넘침
- **해결**: `ResizeObserver`로 컨테이너의 실제 `clientWidth`/`clientHeight`를 측정하고, PDF 실제 규격(595.28 × 841.89pt)에 맞는 정확한 픽셀 크기를 JS에서 계산해 적용. CSS만으로 해결하지 않고 JS 실측으로 전환

### A3. 모바일에서 인증서가 아예 보이지 않음

- **증상**: 데스크톱에서는 정상 출력되던 인증서 PDF 미리보기가 모바일 브라우저에서는 빈 화면
- **원인**: 모바일 브라우저(iOS Safari, 모바일 Chrome 등)는 `<iframe>` 안에 PDF를 인라인 렌더링하는 기능을 데스크톱만큼 지원하지 않음
- **해결**: 헤드리스 크로미움으로 PDF 1페이지를 미리 스크린샷해 `.jpg`로 변환 → 카드에는 이 이미지를 표시하고, "원본 보기"만 실제 PDF 파일로 연결. 이미지는 어떤 브라우저에서도 100% 표시되므로 근본적인 해결

### A4. 대표이사 서명 줄에서 이름 중간이 줄바꿈됨

- **증상**: 모바일에서 "창호종합건설(주) 대표이사 이"까지 나오고 "진규"가 다음 줄로 넘어감
- **원인**: 회사명, 직함, 이름을 공백으로 이어 붙인 한 문단으로 처리해, 화면 폭이 좁아지면 브라우저가 임의의 공백에서 줄바꿈함
- **해결**: "회사명"과 "직함 + 이름"을 처음부터 별도 줄로 분리하고, 이름 부분에는 `white-space: nowrap`을 적용

### A5. 헤더 서브메뉴가 클릭 후에도 닫히지 않음

- **원인**: 드롭다운 표시를 순수 CSS `:hover`/`:focus-within`으로만 제어해, 클릭(선택)이라는 이벤트 자체에는 반응하지 않았음
- **해결**: JS `useState`로 열림 상태를 직접 관리(`onMouseEnter`/`onMouseLeave`)하고, 서브메뉴 링크의 `onClick`에서 명시적으로 상태를 닫음. CSS의 hover 트리거 규칙은 완전히 제거해 두 제어 방식이 충돌하지 않도록 함

## B. 백엔드 환경 설정 (상세)

공지사항 기능을 위해 Vercel Blob을 처음 도입하면서 실제로 겪은 순서 그대로 기록. 결과적으로 **"스토어는 Public으로, 환경변수 설정 후에는 항상 재배포"** 두 가지만 지켰어도 아래 4건은 전부 피할 수 있었다.

### B1. Blob 스토어를 Private로 생성해 업로드 전부 실패

- **증상**: 서버 500 에러
- **에러**: `Vercel Blob: Cannot use public access on a private store.`
- **원인**: Storage → Create Database → Blob으로 스토어를 만들 때 접근 모드를 별도로 확인하지 않아 기본값(Private)으로 생성됨. 코드는 방문자가 로그인 없이 첨부파일을 볼 수 있도록 모든 `put()`에 `access:'public'`을 지정하고 있어 충돌
- **확인**: 스토어 Settings 화면에 "*The access mode cannot be changed after creation.*"라고 명시 — 한번 Private로 만들면 되돌릴 수 없음
- **해결**: 기존 스토어는 폐기하고, 생성 단계에서 **Public**을 명시적으로 선택해 새로 생성

### B2. 이전 스토어가 남아있어 새 스토어를 못 찾음

- **증상**: 서버 500 에러
- **에러**: `Vercel Blob: This store does not exist.`
- **원인**: B1의 Private 스토어를 프로젝트에서 정리하지 않은 채 Public 스토어를 새로 만들어 같은 이름으로 연결 — 두 스토어가 동시에 프로젝트에 연결되며 배포가 참조하는 스토어 식별자가 꼬임
- **해결**: 예전 Private 스토어를 프로젝트 Storage 목록에서 완전히 삭제 → Public 스토어 하나만 남은 상태에서 재배포

> 교훈: 스토어 이름을 재사용하지 말고, 잘못 만든 스토어는 새로 만들기 *전에* 먼저 정리한다.

### B3. 환경변수를 추가해도 실제 배포에는 반영되지 않음

- **증상**: `ADMIN_PASSWORD`를 대시보드에 저장했는데도 로그인이 계속 실패
- **원인**: Vercel은 환경변수를 **배포 시점**에 고정한다. 값을 추가/변경해도 이미 떠 있는 배포에는 적용되지 않음
- **해결**: Deployments 탭에서 최신 배포를 **Redeploy**해야 새 값이 반영됨. 이후 절차에 "환경변수 변경 → 반드시 재배포"를 표준 단계로 고정

### B4. 첨부파일 클릭 시 다운로드가 시작되지 않음

- **증상**: 첨부파일 링크를 클릭하면 저장 대화상자 없이 그냥 이미지가 새 탭에 열림
- **원인**: 파일이 사이트와 다른 도메인(`*.public.blob.vercel-storage.com`)에 있어, HTML의 `<a download>` 속성이 브라우저 정책상 무시됨(교차 출처에서는 미동작)
- **해결**: `put()`이 반환하는 `blob.url` 대신, 강제 다운로드용으로 별도 제공되는 **`blob.downloadUrl`**을 링크에 사용

```ts
// app/lib/notices.ts
interface NoticeFile {
  name: string;
  url: string;
  downloadUrl: string;  // 다운로드는 반드시 이 값 사용
  size: number;
}
```

### B5. 공지 수정 직후에도 예전 내용이 보임

- **증상**: 제목/내용을 수정하고 저장했는데 공개 페이지에는 한동안 이전 내용이 계속 노출
- **원인**: 공지 수정은 같은 파일 경로(`notices-data/{id}.json`)를 덮어쓰는 구조인데, Blob의 CDN이 이전 응답을 기본값(최대 1개월)만큼 캐시하고 있어 "같은 URL"에 대해 예전 내용을 계속 서빙
- **해결**: ① 읽을 때 URL 끝에 `?t={timestamp}` 캐시버스팅 쿼리를 붙여 매번 새 요청으로 취급되게 함 ② 저장할 때 `cacheControlMaxAge: 60`(허용 최솟값인 1분)으로 설정해 캐시 잔존 시간 자체를 최소화

```ts
// app/lib/notices.ts
function bust(url: string) {
  return `${url}${url.includes("?") ? "&" : "?"}t=${Date.now()}`;
}
// 조회 시: fetch(bust(meta.url), { cache: "no-store" })
```

신규 작성은 매번 새 `id`로 새 경로를 쓰기 때문에 이 문제가 없었고, "수정" 기능을 추가하면서 처음 드러난 문제였다.

### B6. 로그인 세션 서명에 Node crypto를 쓸 수 없음

- **배경**: Next.js의 `middleware.ts`는 기본적으로 **Edge 런타임**에서 실행되며, Node.js 전용 모듈(`crypto.createHmac` 등)을 사용할 수 없음
- **해결**: Node crypto 대신 **Web Crypto API**(`crypto.subtle`)로 HMAC-SHA256 서명을 구현 — 이 API는 Edge와 Node 런타임 양쪽에서 동일하게 동작하므로 미들웨어와 서버 액션에서 같은 코드를 공유 가능

### B7. 첨부파일 업로드 용량 제한

- **원인**: Next.js Server Actions는 기본 요청 본문 크기 제한이 있어, 큰 첨부파일 업로드 시 거부될 수 있음
- **해결**: `next.config.ts`에서 `experimental.serverActions.bodySizeLimit`을 `20mb`로 상향 설정

## C. 검증 방법론 노트

### C1. 헤드리스 브라우저 테스트 스크립트의 타이밍 함정

실제 앱 버그가 아니라 **검증 스크립트 자체의 결함**으로 오진했던 사례가 여러 번 있었다. 다음 프로젝트의 자동 검증에도 그대로 적용할 원칙:

- `page.waitForLoadState('networkidle')`만으로는 서버 액션의 리다이렉트 완료를 보장하지 못함 → 목적지 URL을 `page.waitForURL()`로 명시적으로 기다려야 신뢰 가능
- 같은 스크립트를 개발 서버가 **Fast Refresh로 재컴파일 중**일 때 실행하면 클릭이 엉뚱한 결과로 이어질 수 있음 — 서버가 안정된 뒤 재검증해서 재현되는지 확인
- `curl`로 Next.js 페이지를 확인할 때, 응답이 React 서버 컴포넌트 스트리밍 페이로드(RSC)인 경우 일반 정규식 파싱은 신뢰할 수 없음 — 렌더링된 DOM(`innerText`) 기준으로 최종 확인
- 인프라 캐시 지연(B5)과 스크립트 타이밍 결함은 증상이 비슷하므로, 코드를 고치기 전에 **어느 쪽이 원인인지 먼저 격리**해서 재현한다

## D. 다음 프로젝트를 위한 사전 체크리스트

- [ ] Blob 스토어는 **생성 단계에서부터 Public**으로 선택한다 (생성 후 변경 불가)
- [ ] 스토어를 다시 만들어야 한다면, 새로 만들기 **전에** 기존 스토어를 프로젝트에서 정리한다
- [ ] 환경변수를 추가/변경한 뒤에는 **반드시 Redeploy**한다
- [ ] `html`이 아니라 `body`에만 `overflow-x: hidden`을 건다
- [ ] PDF 첨부는 처음부터 "이미지 미리보기 + 원본 PDF 링크" 2단 구조로 설계한다
- [ ] 같은 경로를 덮어쓰는 데이터(게시물 수정 등)는 캐시버스팅과 `cacheControlMaxAge` 최소화를 처음부터 넣는다
- [ ] Blob 첨부파일 다운로드 링크는 `url`이 아니라 `downloadUrl`을 쓴다
- [ ] 미들웨어에서 서명/암호화가 필요하면 Node `crypto`가 아니라 Web Crypto API를 쓴다
